# Shop Bot

بوت متجر Telegram مكتوب بالكامل بـPython، مع واجهة `InlineKeyboard` داخل الرسائل وقاعدة SQLite واحدة: `data.db`.

## التشغيل

1. أنشئ بيئة افتراضية وثبّت الحزم: `pip install -r requirements.txt`.
2. انسخ `.env.example` إلى `.env` وأدخل الأسرار في متغيرات البيئة فقط. لا تضع أي مفتاح في المصدر.
3. شغّل: `python bot.py`.

## Docker

انسخ `.env.example` إلى `.env` ثم شغّل `docker compose up -d --build`. تُحفظ قاعدة البيانات في مجلد `data/` على الخادم ولا تُضمّن داخل الصورة.

## ما هو منفّذ

- تسجيل مستخدمين، إحالات لا يمكن تعديلها (مكافأة 0.5 Credit)، سجل History وCredit Ledger ذري.
- قائمة منتجات 10 لكل صفحة، تفاصيل مع صور ImgBB، والعودة لنفس الصفحة.
- شراء ذري ثم تنزيل ZIP من GitHub مع 3 محاولات واسترداد تلقائي عند فشل التسليم.
- فواتير Telegram Stars ديناميكية (`XTR`) بـpayload فريد، والتحقق في pre-checkout ومنع تكرار الشحنة بواسطة سجل payments.
- `StorageManager` يعزل GitHub ويضمن حجز المساحة داخل transaction قبل الرفع.

## إعداد التخزين والإدارة

يُنشئ النظام مستودعات خاصة تلقائياً (مثل `storage-001`) ويحفظ كل ملف ZIP كـGitHub Release Asset مستقل، لا كملف داخل المستودع. سياسة المشروع هي 4 GiB كحد إجمالي داخلي للمستودع، وملف أقل من 2 GiB لكل Release Asset. موقع الملف ورابطه ومعرّف الـRelease محفوظة في قاعدة البيانات.

معرّفا المديرين مضبوطان كما وردا في المواصفات. قبل الإنتاج، أضف واجهات إدارة إدخال المنتج/الصور/الملف وتنفيذ إنشاء المستودعات؛ الخدمات الحالية هي نقطة التكامل المقصودة ولا ينبغي للـhandlers الاتصال بـGitHub مباشرة.
